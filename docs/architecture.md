# 职责边界

这里用少量模块表达一个可运行的执行主线，不照搬完整产品的目录。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `protocol.py` | 消息、模型回复、工具请求与声明 | 供应商通信、执行策略 |
| `llm.py` | 调用方实现的模型接口 | 账号、重试、缓存、费用治理 |
| `turn.py` | 进程内轮次身份、忙碌状态和终态 | 数据库、恢复、任务队列 |
| `agent_loop.py` | 模型与工具之间的顺序推进、执行上限 | 工具实现、资源隔离 |
| `context.py` | 会话历史、消息副本和工具消息配对 | 摘要、检索、长期记忆 |
| `history.py` | JSON历史版本与完整性校验 | 执行检查点、审批或任务恢复 |
| `events.py` | 每轮事件身份、顺序和数据边界 | 模型Token流、持久事件总线 |
| `operations.py` | 注册、参数校验、审批与执行回执 | OS 沙箱、宿主权限、资源租约 |
| `workspace.py` | 显式根目录下的有界只读工具 | 文件编辑、命令执行、OS沙箱 |
| `api.py` | 公共入口与模块组合 | 桌面应用或业务后端 |
| `integrations/` | 可选框架与消息格式适配 | 自动装配完整 Agent 产品 |

调用主线：

```text
AgentRuntime.run
  → 取得当前 Session 的轮次所有权
  → Agent Loop
      → 读取当前输入视图
      → ChatModel.complete
      → 校验工具批次
      → Operations 校验参数、请求审批、执行已注册工具
      → 保存工具结果，继续调用模型
  → 确认完成、达到上限或失败
```

`Session.snapshot()` 返回副本，模型与审批回调不能借输入对象改写内部历史或工具定义。
工具按返回顺序执行，避免社区版承诺复杂的并行写入语义。

执行状态在内存中，宿主可通过JSON保存和加载聊天历史。模型与工具由宿主注入；
核心既不拥有系统资源，
也不连接 TraceMind 的任何私人服务。生产应用仍需自行实现认证、资源隔离、
幂等、审计、持久存储和运行监控。

## 事件与历史分开

运行事件用于观察当前执行，消息历史用于下一次模型输入。把两者混在一起，
容易把界面状态、审批过程或工具输出重复塞入上下文，因此事件不会自动变成模型消息。
`run()`和`stream()`使用同一条执行路径；流式入口通过32条有界缓冲传递事件，
消费者退出时取消并等待生产任务，避免留下无人管理的执行。

历史JSON是带版本的普通数据。加载它只建立新的内存会话，不能恢复旧任务、批准操作，
也不触发任何工具。它没有私有产品的协调账本、重放、后台worker或恢复策略。
